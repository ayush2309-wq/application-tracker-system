About This System

Full architecture, technology stack, and algorithm details for the Application Tracker System

Backend Technologies

Python 3.12 Core language

All business logic is written in Python 3. The codebase uses dataclasses to define the three core domain objects — JobRequirement, Application, and MatchResult — which gives typed, immutable-friendly value objects without boilerplate.

  • src/models.py — data classes
  • src/matcher.py — scoring engine
  • src/tracker.py — orchestration
  • src/notifier.py — notifications
  • src/logger.py — logging setup
Flask 3 Web framework

Flask is a lightweight WSGI micro-framework. app.py defines all routes using Flask's @app.route decorator. The Werkzeug WSGI toolkit (bundled with Flask) handles HTTP parsing, while Jinja2 (also bundled) renders the templates.

  • Routes: GET/POST for pages; GET for JSON API
  • Flash messages via flask.flash
  • URL building via flask.url_for
  • JSON responses via flask.jsonify
  • Debug mode controlled by FLASK_DEBUG env var
JSON Files Data persistence

All data is stored as flat JSON files in the data/ directory — no external database required. Python's built-in json module reads and writes these files. The web layer serialises dataclass instances via __dict__.

  • data/job_requirements.json — job postings
  • data/applications.json — submitted applications
  • data/results.json — cached match results (CLI)
logging Structured logging

Python's standard logging module with RotatingFileHandler keeps the log directory lean. A structured JSONL event log (logs/events.jsonl) records each match event as a one-line JSON object for easy machine processing.

  • logs/tracker.log — rotating human-readable log
  • logs/events.jsonl — structured JSON event log
  • Max file size 1 MB · 5 backup files

Frontend Technologies

Jinja2 Server-side templating

Jinja2 is Flask's built-in template engine. Templates inherit from templates/base.html using {% raw %}{% extends %}{% endraw %} / {% raw %}{% block %}{% endraw %}. Python objects (jobs, applications, results) are passed from route handlers and rendered directly in HTML without any client-side framework.

  • Template inheritance — DRY shared layout
  • Filters: |capitalize, |format, |length
  • Globals: custom status_badge() helper
Bootstrap 5.3 CSS framework

Bootstrap 5 provides the responsive grid, utility classes, card components, tables, badges, forms, and the collapsible mobile navbar — all without jQuery. Loaded via CDN with Subresource Integrity (SRI) hashes to prevent supply-chain attacks.

  • 12-column responsive grid (col-md-*)
  • Utility classes: spacing, colour, flexbox
  • Components: cards, tables, badges, forms, alerts, navbar
  • Bootstrap Icons 1.11 — icon font via CDN
Vanilla JS Client-side interactivity

No JavaScript framework is used. Plain ES2020 JavaScript handles:

  • Live skill-badge preview on the Apply and Post Job forms
  • Status filter buttons on the Results page
  • Text search across applicant name + job title
  • fetch() call to POST /results/run for async re-matching
  • Bootstrap bundle JS for navbar collapse and alert dismissal
CSS3 static/style.css

A small custom stylesheet extends Bootstrap with project-specific components:

  • Score bars — overlaid progress bar + label
  • Stat cards — icon circles, large value text
  • Job cards — hover lift animation
  • Sticky footer — flex-column layout on <body>

Matching Algorithm

Scoring Formula
total_score =
  (req_skills_matched / req_skills_total) × 0.60
+ (pref_skills_matched / pref_skills_total) × 0.20
+ min(experience_years / min_experience_years, 1.0) × 0.20
Component Weight Rationale
Required Skills 60 % Must-have skills are the primary gate
Preferred Skills 20 % Nice-to-have differentiators
Experience 20 % Capped at 1.0 — seniority bonus, not penalty
Status Thresholds
Accepted
≥ 70 %
Waitlisted
45 – 69 %
Rejected
< 45 %

Thresholds are configurable in config.json:

{
  "accept_threshold": 0.70,
  "waitlist_threshold": 0.45
}
Algorithm Pipeline
Load JSON data
Compute component scores
Weighted sum → total score
Rank applicants per job
Assign status & notify

Testing

pytest Unit test framework

The tests/test_matcher.py test suite covers the matching engine with 15 unit tests across four test classes, using pytest.fixture for shared test data.

  • TestComputeMatchScore — score range, edge cases
  • TestDetermineStatus — threshold boundaries
  • TestMatchApplication — multi-job matching, sort order
  • TestRankApplications — ranking order, empty list
Run the tests
$ pip install -r requirements.txt
$ pytest tests/ -v
Start the web UI
$ python app.py
# development (debug on):
$ FLASK_DEBUG=true python app.py
